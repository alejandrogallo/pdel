* Launching Pure Data from a form

A PDEL form can be assembled, laid out, written to a temporary =.pd= file,
and launched in Pure Data directly:

#+begin_src lisp
(pdel-pd:launch-form
 '(osc~ #(440)
   (mtofreq
    (midiin))))
#+end_src

The function returns three values: the UIOP process object, the generated
pathname, and the laid-out assembly.

#+begin_src lisp
(multiple-value-bind (process pathname assembly)
    (pdel-pd:launch-form
     '(osc~ #(440)
       (mtofreq
        (midiin))))
  (declare (ignore assembly))
  (format t "Pd process: ~S~%Patch: ~A~%" process pathname))
#+end_src

Use =:gui nil= for =pd -nogui=, =:pd= to select another executable, and
=:arguments= for extra Pure Data command-line arguments.

* Special Pd records

PDEL distinguishes ordinary =#X obj= nodes from Pd records whose patch-file
syntax is different:

#+begin_src lisp
(msg "set 440")
(msg #("1 2, 0 250 2") (bang))
(text "a canvas comment")
(comment "alias for text")
(floatatom #(5 0 127 0 "" "" ""))
(symbolatom #(10 0 0 0 "" "" ""))
(listbox #(20 0 0 0 "" "" ""))
#+end_src

=msg=, =floatatom=, =symbolatom= and =listbox= are connectable assembly
elements. =text=/=comment= consume a canvas object index but are not treated as
connection sources. Structural records do not consume object IDs:

#+begin_src lisp
(declare -path "else")
(raw "#X coords 0 0 1 1 100 100 1;")
#+end_src

=declare= records are emitted before canvas elements. =raw= records are emitted
after normal elements and connections and are intended for structural Pd syntax,
not arbitrary connectable objects.

* Disassembling Pure Data patches

The Common Lisp disassembler reads ordinary =.pd= text back into the same
=PDEL-ASM:ASSEMBLY-RESULT= representation used by the compiler, then emits
round-tripable PDEL source.

#+begin_src lisp
(defparameter *decompiled*
  (pdel-disassembler:disassemble-pd-file #P"patch.pd"))

(format t "~A~%"
        (pdel-disassembler:disassembly-to-string *decompiled*))
#+end_src

The source generator is topology-aware.  It binds each Pd object exactly once
and uses the language forms already provided by PDEL where they describe the
original graph:

- =let= for object identity and sharing;
- =->= for explicit wiring and cycles;
- =join= for several source endpoints entering one inlet;
- =fanout= for one source endpoint feeding several destinations;
- =in= / =out= for non-zero port numbers;
- =multiple-outlet-bind= when several outlets of one object are consumed;
- =msg=, atom-box compiler forms, =declare=, =raw=, and =raw-object= for the
  corresponding special Pd records.

Nested Pd canvases become =defpdel= definitions with their inlet/outlet signal
kind inferred from =[inlet~]/[outlet~]= versus =[inlet]/[outlet]=.  If a
subpatch name already names a registered bundled PDEL object, the disassembler
reuses that object instead of generating a duplicate definition.

Unknown indexed =#X= records are represented with =(raw-object "...")=.  This
is distinct from structural =(raw "...")=: =raw-object= consumes an object id
and can therefore remain the endpoint of =#X connect= records.

The parser preserves canvas dimensions and object =x/y= positions in the
assembly.  The generated PDEL intentionally leaves layout to the normal PDEL
layout pass.
